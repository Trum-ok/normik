# Профили

Профиль адаптирует набор правил под требования кафедры без форка репозитория:
отключает правила, меняет их уровень, задаёт параметры.

```bash
nk check chapters --profile profiles/my-department.toml
```

Без ключа профиль ищется рядом с исходниками, а если не найден — применяется
встроенный `base`: все правила с их объявленными уровнями.

## Где лежит профиль

Ключ `--profile` не обязателен: `nk` поднимается от проверяемых путей вверх по
дереву каталогов и берёт первый найденный файл.

| Файл | Секция |
|---|---|
| `nk.toml` | весь файл |
| `.nk.toml` | весь файл |
| `pyproject.toml` | `[tool.nk]` |

В одном каталоге порядок такой же: `nk.toml` перед `.nk.toml`, оба — перед
`pyproject.toml`. Файл `pyproject.toml` без секции `[tool.nk]` пропускается,
поиск продолжается выше: чужая сборка не должна выдавать себя за профиль.

Поиск начинается с общего каталога всех проверяемых путей — профиль на прогон
один, иначе части исходников проверялись бы по разным правилам. Явный
`--profile` отменяет поиск.

В `pyproject.toml` ключи профиля те же, только с префиксом секции:

```toml
[tool.nk]
name = "Кафедра N"
disable = ["G732-6.5.1-reference-word"]

[tool.nk.rules."G732-5.3.2.1-keywords-count".params]
keywords_max = 20

[tool.nk.elements.aliases]
"СПИСОК ЛИТЕРАТУРЫ" = "СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ"
```

Какой файл подхватился, показывает `nk profile show` строкой «Источник».

## Формат

```toml
name = "Кафедра N"
extends = "base"

# Отключить правила целиком.
disable = ["G732-6.5.1-reference-word"]

# Понизить уровень: нарушение показывается, но не влияет на код возврата.
[rules."G732-6.4.5-heading-depth"]
severity = "info"

# Поднять уровень.
[rules."G732-6.6.2-reference-word"]
severity = "error"

# Переопределить параметры. Незаданные берутся из объявления правила.
[rules."G732-5.3.2.1-keywords-count".params]
keywords_max = 20

# Наименования структурных элементов, принятые кафедрой вместо стандартных.
[elements.aliases]
"СПИСОК ЛИТЕРАТУРЫ" = "СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ"
```

| Ключ | Значение |
|---|---|
| `name` | имя профиля, попадает в шапку вывода |
| `extends` | имя встроенного профиля-основы; наследование на один уровень |
| `standard` | [стандарт](#стандарт-и-свой-источник-требований), пункты которого попадают в находки |
| `source.title` | название [своего источника требований](#стандарт-и-свой-источник-требований) |
| `disable` | идентификаторы правил, которые не запускаются |
| `enable` | идентификаторы правил, [выключенных по умолчанию](#правила-выключенные-по-умолчанию) |
| `rules."ID".severity` | `error`, `warning` или `info` вместо объявленного |
| `rules."ID".clause` | пункт своего источника вместо пункта стандарта |
| `rules."ID".params` | значения параметров правила |
| `elements.order` | [состав и порядок](#состав-и-порядок) структурных элементов |
| `elements.roles` | [роли элементов](#роли): какой элемент чем является для правил |
| `elements.aliases` | наименования элементов кафедры и их канонические наименования |
| `appendix.letters` | [обозначения приложений](#обозначения-приложений) по порядку |

Готовый образец для копирования —
[`profiles/example-university.toml`](https://github.com/Trum-ok/normik/blob/master/profiles/example-university.toml).

## Структурные элементы

Наименования элементов — общий словарь всех правил о структуре: состав, порядок,
регистр заголовков, содержание реферата. Если кафедра называет элемент иначе,
чем стандарт, наименование объявляется синонимом:

```toml
[elements.aliases]
"СПИСОК ЛИТЕРАТУРЫ" = "СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ"
"ОБОЗНАЧЕНИЯ И СОКРАЩЕНИЯ" = "ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ"
```

Слева — как пишет кафедра, справа — каноническое наименование; регистр и знаки
препинания значения не имеют. Наименование справа проверяется по составу: синоним,
ведущий к тому, чего в составе нет, — ошибка профиля, иначе опечатка молча
выключала бы опознание элемента.

### Состав и порядок

Кафедре синонимов обычно хватает. Другой источник требований — другой ГОСТ,
положение вуза — задаёт свои состав и порядок целиком:

```toml
[elements.order]
"ПРЕДИСЛОВИЕ" = 1
"СОДЕРЖАНИЕ" = 2
"ОБОЗНАЧЕНИЯ И СОКРАЩЕНИЯ" = 3
"ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ" = 4
"ВВЕДЕНИЕ" = 5
"ЗАКЛЮЧЕНИЕ" = 6
"ПРИЛОЖЕНИЕ" = 7
```

Наименования в TOML пишутся в кавычках: ключ из кириллицы иначе не разбирается.

Число — ранг, место элемента в порядке. Общий ранг у элементов, которые занимают
одно место и заменяют друг друга: отдельный перечень терминов и объединённый
перечень терминов и сокращений идут под одним номером.

Состав задаёт и то, что вообще считается структурным элементом: заголовок с
наименованием, которого в `order` нет, для правил обычный заголовок раздела.
Поэтому `order` заменяет перечень целиком, а не дополняет его — иначе в профиле
оставались бы элементы источника, от которого уходили.

Порядок из профиля попадает и в текст находки: правило
[`G732-4-elements-order`](rules/G732-4-elements-order.md) называет тот порядок,
по которому проверяется этот отчёт.

### Роли

Правило спрашивает словарь не про наименование, а про роль: не «это РЕФЕРАТ?»,
а «это элемент, где ведут реферат?». Наименование под ролью задаёт профиль:

```toml
[elements.roles]
abstract = ["РЕФЕРАТ"]
contents = ["СОДЕРЖАНИЕ"]
terms = ["ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ"]
abbreviations = ["ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ", "ОПРЕДЕЛЕНИЯ ОБОЗНАЧЕНИЯ И СОКРАЩЕНИЯ"]
bibliography = ["СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ"]
appendix = ["ПРИЛОЖЕНИЕ"]
```

| Роль | Кто её спрашивает |
|---|---|
| `abstract` | правила о составе и оформлении реферата |
| `contents` | зачёт содержания по `\tableofcontents` |
| `terms` | перечень терминов: порядок, вводная фраза, тире |
| `abbreviations` | перечень сокращений: свой либо объединённый |
| `bibliography` | зачёт списка источников по окружению библиографии |
| `appendix` | опознание заголовка «ПРИЛОЖЕНИЕ А» |

Роль может занимать несколько наименований и может пустовать. Пустая роль — не
ошибка: у источника требований, где нет реферата, правила о реферате молчат.

Без секции `roles` роли берутся по умолчанию, но только теми наименованиями,
которые остались в составе. Роль, названная явно, заменяет умолчание целиком,
а наименование в ней обязано быть в `order`.

Состав обязательных элементов задаётся параметрами правила
[`G732-4-required-element-missing`](rules/G732-4-required-element-missing.md).
Убрать одно требование, оставив остальные:

```toml
[rules."G732-4-required-element-missing".params]
excluded = ["РЕФЕРАТ"]
```

Задать перечень целиком:

```toml
[rules."G732-4-required-element-missing".params]
required = ["СОДЕРЖАНИЕ", "ВВЕДЕНИЕ", "ЗАКЛЮЧЕНИЕ", "СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ"]
```

В обоих списках наименования пишутся по стандарту либо синонимами кафедры.
Наименование, которого нет ни там ни там, проверку не выключает: элемент просто
не найдётся, и правило сообщит о его отсутствии — опечатка в профиле остаётся
видимой.

## Стандарт и свой источник требований

Одно и то же требование записано в нескольких стандартах под разными пунктами.
Какой из них попадёт в находку, решает профиль:

```toml
standard = "G732"
```

| Значение | Стандарт |
|---|---|
| `G732` | ГОСТ 7.32-2017, по умолчанию |
| `GR2105` | ГОСТ Р 2.105-2019 |

Правило, которого в выбранном стандарте нет, пункта в находке не получает —
как и типографика, которую стандарты не регулируют.

Положение вуза — тоже источник требований, со своей нумерацией. Там, где оно
расходится со стандартом, находка обязана ссылаться на него, а не на пункт,
который требует другого:

```toml
[source]
title = "Положение МГТУ им. Н.Э. Баумана № 01-01-ПЛ-016 01-2024"

[rules."G732-6.17.4-appendix-sequence"]
clause = "10.11"
```

Пункт, объявленный профилем, старше пункта стандарта. Объявить пункт, не назвав
источник, нельзя: непонятно, чей он.

## Обозначения приложений

Обозначения приложений — знаки строки, идущие по порядку:

```toml
[appendix]
letters = "123456789"
```

По умолчанию это прописные буквы кириллицы без Ё, З, Й, О, Ч, Ъ, Ы и Ь.
Готовые наборы — латиница без I и O, арабские цифры — выписаны в комментариях
встроенного профиля `base`, откуда их копируют.

Набор задаёт и допустимые обозначения, и их порядок, и то, какой номер получит
рисунок или таблица внутри приложения. Повтор знака — ошибка профиля: по
обозначению определяется место приложения в последовательности, а у
повторённого знака мест было бы два.

Набор один. Если источник требований допускает две системы обозначений —
скажем, и цифры, и латиницу, — выбрать в профиле придётся одну.

## Готовые профили

Кроме `base` в поставку входит профиль под положение вуза:

```bash
nk check chapters --profile bmstu-vkr
```

| Профиль | Что описывает |
|---|---|
| `base` | чистый ГОСТ 7.32-2017, все правила с объявленными уровнями |
| `bmstu-vkr` | ВКР по положению МГТУ им. Н.Э. Баумана № 01-01-ПЛ-016 01-2024 |

`bmstu-vkr` показывает, как настраивается источник требований, который ссылается
на ГОСТ, но расходится с ним в частностях: свой состав элементов, объединённый
перечень обозначений и сокращений, реферат без ключевых слов, приложения под
цифрами, разделы основной части без разрыва страницы. Пункты в находках
остаются пунктами 7.32.

Профиль кафедры наследуется от готового и правит своё:

```toml
name = "Кафедра ИУ-N"
extends = "bmstu-vkr"

disable = ["G732-6.5.1-reference-word"]
```

## Правила, выключенные по умолчанию

Часть правил даёт много находок, а требованием стандарта не является — такие
выключены по умолчанию и включаются явно:

```toml
enable = ["NK-STYLE-preposition-nbsp"]
```

На странице такого правила стоит пометка о том, что оно выключено. Ключ
`--select` тоже включает их: `nk check chapters --select NK-STYLE-preposition-nbsp`.

## Проверка профиля

Опечатка в идентификаторе правила — ошибка, а не молчаливое отключение
проверки: профиль, ссылающийся на несуществующее правило, не запускается.

Посмотреть, что получилось после наследования и переопределений:

```bash
nk profile show --profile profiles/my-department.toml
```

Команда печатает источник профиля, итоговый уровень каждого правила, состояние —
включено или отключено — и действующие параметры. Без ключа `--profile` профиль
ищется от текущего каталога.

## Что настраивать имеет смысл

- **Требования кафедры расходятся со стандартом.** Например, принято сокращение
  «рис.» в ссылках: правило
  [`G732-6.5.1-reference-word`](rules/G732-6.5.1-reference-word.md)
  отключается.
- **Пороги.** Диапазон числа ключевых слов, предельная глубина рубрикации —
  параметры, а не константы.
- **Наименования и состав структурных элементов.** Кафедра пишет «СПИСОК
  ЛИТЕРАТУРЫ» или не требует реферата — это синонимы и `excluded`, а не
  отключение правила целиком.
- **Строгость сборки.** Уровень определяет, падает ли CI: `error` — да,
  `warning` и `info` — нет.

Параметры каждого правила перечислены на его странице в разделе
[Правила](rules/index.md).
