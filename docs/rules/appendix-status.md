# appendix-status

**Под обозначением приложения не указан его статус.**

| | |
|---|---|
| Категория | Приложения |
| Источник требования | стандарт |
| Пункты | ГОСТ Р 2.105-2019 п. 6.3.4 |
| Уровень по умолчанию | <span class="nk-severity nk-severity--error">error</span> |
| Объявлено в | `nk.rules.appendices.appendix_status` |
| Фикстуры | `tests/fixtures/appendix-status/` |
| Автоисправление | нет |

Просматривает первые непустые строки под заголовком приложения и ищет среди
них статус в скобках. Заголовок самого приложения статусу не мешает: он может
стоять и до, и после него.

## Почему это нарушение

Статус говорит, обязательно приложение к исполнению или приведено для
сведения. Без него читающий не знает, требование перед ним или пояснение.

## Как исправить

Добавить под обозначением приложения отдельную строку со статусом
в скобках: `(обязательное)`, `(рекомендуемое)` либо `(справочное)`.

!!! note

    Готовое исправление правило не предлагает: оно принципиально неоднозначно.

## Нарушение

```latex
\newpage
\section*{ПРИЛОЖЕНИЕ А}

Расчёт нагрузки на опору

Опора рассчитана на статическую нагрузку.
```

## Как правильно

```latex
\newpage
\section*{ПРИЛОЖЕНИЕ А}

(обязательное)

Расчёт нагрузки на опору

Опора рассчитана на статическую нагрузку.

\newpage
\section*{ПРИЛОЖЕНИЕ Б}

(справочное)

Схема установки
```

## Настройка

Отключить правило либо изменить его уровень [профилем](../profiles.md):

```toml
disable = ["appendix-status"]

[rules."appendix-status"]
severity = "info"
```
